# Delivery Rush — Vision

## Core Vision (Primary)

Delivery Rush is a one-thumb arcade experience where players *chase the combo*—each delivered order raises a multiplier that boosts coins, but one crash or missed dropoff resets it to 1. The fantasy is being a skilled courier weaving through traffic, throttling into tight corners, and nailing every run under pressure. Success means the player leaves feeling exhilarated by their own skill and hungry to "play one more run." The core emotional beat: that moment before a tight corner where you decide whether to brake or stay on throttle.

## Secondary Goals (What Success Looks Like)

- **Instant mastery:** Players understand controls in seconds and grasp the delivery loop in their first run. No tutorials, no friction.
- **Skill expression through throttle timing:** Casual players complete deliveries. Skilled players chain combos and chase high scores. The same mechanic serves both.
- **Snackable sessions fit mobile moments:** 45–90 seconds per run respects player time. Die, tap, play again. No progression walls, no wait timers, no fomo.
- **Accessible arcade challenge:** Color-blind–distinct buttons, directional glyphs (not color alone), keyboard playable. All-ages target with no narrative or violence.

## Design Principles That Serve This Vision

- **Every decision prioritizes throttle timing.** Steering is buffered (commits at intersections), not real-time—forcing the player to think ahead, not react. Traffic density, order timers, and vehicle speed all exist to create throttle-timing dilemmas.
- **Combo is the only persistent reward within a run.** No XP, no unlocks mid-run, no power-ups. Just: complete delivery → multiplier rises → next order worth more coins. This keeps attention on the immediate challenge.
- **Visual, audio, and haptic feedback celebrate every throttle decision.** Screen shake on acceleration, satisfying SFX on lane changes, haptic pulse on perfect turns. Juice sells velocity.
- **The procedural city regenerates each run.** No memory, no unlocks. Each run is a fresh puzzle: new order route, new traffic, new opportunity to chain a better combo. Replayability comes from emergent challenge, not progression loops.

## Anti-Vision (What This Game Is NOT)

- **Not a narrative-driven game.** Story is functional (why you deliver), not the draw. Emoji order glyphs, minimal context. Player attention stays on the challenge, not cinematics.
- **Not a progression/collection game.** No permanent upgrades that carry over (vehicles and cards are cosmetic, not power). The challenge resets every run. Retention comes from "one more run," not FOMO or grinding.
- **Not realistic or challenging in the Dark Souls sense.** This is arcade difficulty: fair, immediate, punishing but never unfair. Players always see why they crashed. No permadeath, no hidden mechanics. Casual players can finish a run; skilled players can chain 8× combos.

## Vision Decision Framework

When a design debate surfaces, ask:

1. **Does this choice strengthen throttle-timing dilemmas?** (e.g., "Should we add a nitro boost?" Only if it creates a throttle choice—use it early to speed, or hold it for a corner?)
2. **Does it keep the player chasing the next combo?** (e.g., "Should we add cosmetic rewards for high scores?" Only if it doesn't interrupt the run or add pause friction.)
3. **Does it respect the 45–90 second session?** (e.g., "Should we add a story mode?" No—story scales to hours, not seconds.)
4. **If unclear, does it serve a secondary goal important enough to justify complexity?** (e.g., "Should we include colorblind support?" Yes—accessibility serves all-ages target.)
5. **If it weakens both, we cut it.** Scope clarity is a feature.

- [x] Vision is 2–3 paragraphs, readable aloud to a new team member in under 2 minutes.
- [x] Every major mechanic (throttle, buffered steer, combo, order timer, traffic) traces back to the vision as justification.
- [x] Secondary goals are outcomes of nailing the primary vision, not goals in themselves.
- [x] Anti-vision is written (what the game explicitly is not).
- [x] Vision could serve as a tiebreaker in a design dispute (e.g., "Does this feature serve throttle timing? No? Cut it.").
